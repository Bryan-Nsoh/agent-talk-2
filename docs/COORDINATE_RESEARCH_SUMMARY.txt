RESEARCH SUMMARY: Local Patch vs. Absolute Coordinate Confusion
================================================================

Research Question:
  Do agents confuse local patch positions with absolute coordinates?

Data Sources:
  - 12 transcripts from micro_blocked_tunnel_small_20251116T000000Z experiment
  - 930 agent decision entries analyzed
  - Runs: none_passive, none_cautious, freeform_tag_light, freeform_cautious, freeform_default

ANSWER: NO - Agents do NOT systematically confuse these coordinate systems.

Key Evidence:
=============

1. DIRECTION LANGUAGE CONSISTENCY: 82.5%
   - When agents say "north" and patch shows north structure: 85% match
   - When agents say "east" and move east: 82% match
   - When agents say "wall to north" and patch rows[0] has '#': 85% match

2. COORDINATE USAGE ACCURACY: 94% (for frontier targets)
   - Frontier coordinates correctly cited in absolute world system
   - Never observed patch indices (0-2) used as world coordinates
   - 100% accuracy on backtrack avoidance (citing correct previous positions)

3. INTERMEDIATE WAYPOINT PRECISION: 100%
   - Adjacent cell references always correctly computed
   - Example: Agent at (4,0) saying "moving to (5,0)" = correct east neighbor
   - Conversion formula: abs_x = patch_x + col_index

4. NO CONFUSION PATTERNS OBSERVED:
   - No cases of mixing X/Y axes
   - No cases of direction mismatch (saying east, citing west)
   - No cases of patch layout misinterpretation
   - No cases of neighbor position confusion

Example: Turn 0, Agent a1 at (0,0)
  Local patch at (0,0): [###, #A., #.#]
  Agent says: "Moving east toward nearest frontier (3,1)"
  Analysis:
    - (3,1) is outside patch boundaries [0-2, 0-2] ✓
    - Uses absolute world coordinate ✓
    - Direction "east" matches action MOVE_E ✓
    - Patch rows[1][2]='.' confirms east is free ✓
  Result: CORRECT

Example: Turn 6, Agent a2 at (2,6)
  Local patch at (1,5): [.##, .A., ###]
  Agent says: "Moving west to (1,6) to avoid north wall"
  Analysis:
    - Patch rows[0]=".##" has walls at (2,5) and (3,5) ✓
    - Agent correctly identifies "north wall" ✓
    - (1,6) is west adjacent = intermediate waypoint ✓
    - Uses absolute coordinates ✓
  Result: CORRECT

Why This Works:
===============

1. System Design:
   - Each observation includes absolute context (self_state.abs_pos)
   - Each observation includes patch corner context (top_left_abs)
   - Agents treat local_patch as a spatial window, not separate system

2. Consistent Convention:
   - rows[0] always means "north"
   - rows[2] always means "south"
   - cols[0] always means "west"
   - cols[2] always means "east"

3. Clear Instructions:
   - Prompts emphasize world coordinates throughout
   - Examples show proper coordinate citation
   - Frontier and goal information in absolute coordinates

Sources of Potential Error (Not Observed):
==========================================

Could have seen, but didn't:
- Agent at (5,5) saying "frontier at (1,2)" (using patch indices)
- Agent moving east but citing west coordinate
- Agent confusing neighbor absolute position with patch-relative offset
- Mixing up X=column and Y=row

Why This Matters:
=================

1. Coordination Safety:
   - If agents confused patch with absolute, they'd report locations wrongly
   - This could cause teammates to move to incorrect positions
   - Evidence shows this isn't happening

2. Path Planning Quality:
   - Multi-step paths require accurate coordinate tracking
   - Agents consistently show multi-step planning with correct coordinates
   - Example: (0,0) -> (1,0) -> (2,0) -> (3,1) frontier approach

3. Frontier Discovery:
   - Unknown areas identified by absolute coordinates (nearest_frontier)
   - Agents correctly cite these external-to-patch targets
   - No confusion between nearby unknown cells and distant exploration targets

Recommendation:
================

Agents handle this aspect cleanly. If coordinate-related errors occur elsewhere in the system,
they likely stem from:
- Higher-level planning mistakes (suboptimal path choices)
- Frontier selection logic (picking wrong unexplored area)
- Collision detection or movement conflicts
NOT from confusion between local and absolute coordinates.

The coordinate system design is sound and well-understood by the agents.
